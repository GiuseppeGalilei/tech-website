## Configuring the System

Follow these steps:

- Install Ubuntu 22.04 LTS on the SSD using the simple GUI, selecting EXT4 with LUKS encryption.
- Obtain a static IP from your router.
- Set up an SSH server.
- Install CasaOS and set its web interface to a port other than 80, 81, or 443 (as Nginx will need them).
- Format the archive HDD to LUKS encrypted EXT4 as well and set the correct options to automount it on startup in the right place, while also unlocking it.
- Give ownership of the **/DATA** folder to the **root** and **www-data** users, as needed by some containers (namely Nextcloud and Syncthing).
- Free port 53 from `resolved service`, PiHole will use it.
- Use the CasaOS AppStore to install all the required containers.

## Configuring the Containers

A quick note: upon installation, CasaOS configures each container with a default username and password. Remember to change them.

### MariaDB

This container may be considered optional, because all other containers we installed, when needed, come with their own SQLite instance. However, using SQLite is not recommended for uses other than development or testing.

We’ll use **Adminer** to log into MariaDB and create the databases for Nextcloud and Photoprism using the SQL console.

Then, using **Portainer**, we can connect the Nextcloud and Photoprism containers to the MariaDB **network**.
Be sure to check the network settings whenever something is not working, it’s easy to mess this up by redeploying through CasaOS.

### Cloudflared

This gives you remote access to your services, even when behind strict firewalls, NATs, whatever... it just works.
There are several different ways to achieve this. Maybe in the future I’ll explore more of them.

Configuration of this container is very straightforward: just place your token and you are good to go.

However, the full setup is quite more involved. You can find a good tutorial from the guys at Crosstalk Solutions, [here](https://www.youtube.com/watch?v=ZvIdFs3M5ic).

Beware that to use it you need a domain name and that, even on paid plans, the policies are quite strict. Don’t think of watching your Plex movies through it, people have been banned for doing so. Think of it as a simple way to monitor your services from outside, not fully use them.
For that, think of hosting your own proxy. It’s in the plans to try Oracle free tier VPS for this. Stay tuned.

### Pi hole

I install this every time for ad blocking in general.
Here it is also useful for creating a local DNS record for the domain Nextcloud will use, because its app otherwise doesn’t work properly.
Strange, but I’ll link you to the [Reddit thread](https://www.reddit.com/r/NextCloud/comments/1085d05/internal_and_external_access_to_nextcloud_with/) that solved this issue for me, in case you are curious.

To set it up, you just need to follow the wizard, set the local DNS record for Nextcloud, and point your router’s DNS setting to your Pi-hole instance.

Then you can enjoy a much cleaner browsing experience across all your devices. You can whitelist some domains if you want them to still show ads and maybe support them.

### Nextcloud

When installing it, remember to check that its container is connected to the MariaDB network and uses the correct database.

Here things get interesting. You can either use it as-is or, if like me you want to squeeze the last bit of performance out of your system, you can get creative with mount points and play with Nextcloud cache file placement.

For those who want to play:

By default, Nextcloud places each user’s files and caches, such as thumbnails, in the same folder. This is not optimal if you are using a slow HDD as the main archive. So, I decided to keep thumbnails and previews on the SSD, while the actual files still sit on the HDD.

So, I had to:

- install Nextcloud normally
- identify such files
- move them where needed
- set the correct mount points.

To mount my storage folder in Nextcloud, I’ll use the **[external storage app](https://docs.nextcloud.com/server/latest/admin_manual/configuration_files/external_storage_configuration_gui.html)** rather than mounting it in the actual Nextcloud data folder using system mount points.
Nextcloud is quite strict about wanting complete ownership of the files it manages, which all need to pass through its UI to be indexed. Otherwise, you would need to perform manual indexing using the CLI. Feasible, but not recommended. I tried it, then settled on the other approach. It just works better.

Nextcloud also requires you to specify the domains it will be accessed through.

If we want to access it through Cloudflare, we need to set a variable that forces traffic to pass through Nginx locally. Not a huge problem, explained [here](https://youtu.be/p0I8pikm2P4?si=2TgPDBjzW6_F4HDX&t=959).

If everything works, congratulations, the worst has passed!
